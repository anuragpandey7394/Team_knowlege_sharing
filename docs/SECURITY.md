# Foundation verification and boundaries

Every organization-scoped method in runtime OpenAPI is exercised by `tests/integration/tenant-matrix.test.ts`. It supplies valid request bodies with another tenant's authenticated session, then forges resource IDs under the attacker's own organization. Missing test payloads for new routes fail the matrix. `docs/evidence/M09-tenant-matrix.json` records the parameterized route/status matrix without credentials. Earlier integration suites cover role grants, parent/space forgery, hidden drafts, immutable history, comment revisions, private chat ownership, invitation replay, CSRF and active-session revocation.

API responses use no-store, nosniff, frame denial, same-origin referrer policy and a restrictive CSP for data responses. Local Vite documents use a development CSP allowing its inline React refresh bootstrap, controlled inline styles and localhost WebSocket HMR. Hosted production must use the M10 reverse proxy's stricter script policy and HTTPS; this development allowance is not a hosted security claim. Rich text uses a strict server schema and escaped semantic rendering; comments/snippets/questions remain escaped plain text. SQL data parameters are bound; dynamic identifiers exist only in tools with generated names or fixed internal allowlists.

Administrative organization/member/invitation changes, publication, archive/restore and comment moderation write tenant/actor/resource/action/request identifiers. Audit records exclude tokens, emails, passwords and body contents. Request logs serialize method/path, omitting queries and sensitive headers. A real logger test checks a synthetic sensitive sentinel never appears. Safe error responses include request IDs; no stack/provider payload is returned.

`npm run security:check` scans tracked/new project text for credential patterns and checks npm's live advisory database. It fails on missing inventory/advisory metadata, findings or audit failure. Ignored env/cache/build files and unrelated .codex/.agents directories are excluded. The report is a timestamped limited check, not proof against unknown vulnerabilities. `.env.example` and seed identities are explicit synthetic local defaults. Hosted secrets must be injected separately; seed is rejected in production and on nonlocal/unrecognized databases.

GitHub Actions runs the same foundation aggregate with PostgreSQL and Mailpit service containers, pinned action commits, read-only repository permissions and no model/AWS credentials. Checkout/setup-node references were checked against their upstream v7 tags and official repositories: https://github.com/actions/checkout and https://github.com/actions/setup-node. No deployment, Terraform apply or real email send occurs in this workflow. Remote CI execution is reported separately from local verification.
