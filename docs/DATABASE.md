# Database invariants and migration safety

Prisma migrations own application schema; migrations are reviewed SQL committed with application code. Identity/organization tables come first. Later knowledge, jobs and conversations are added with their actual vertical flows rather than unused tables.

Users have UUID IDs, unique lowercase-normalized email (database check enforces normalization), UTC timestamps, and password hashes never serialized to clients. Sessions and action tokens store only unique SHA-256 digests; revocation, expiry and consumption are checked server-side. Membership has a composite organization/user primary key. Every organization operation rechecks membership from the database; client-provided role/user headers are ignored. Organization-scoped resources added later require organization-inclusive unique keys/foreign keys, not UUID possession as authorization.

Organization creation and first Admin insertion will share a transaction in M03. Final-Admin changes must lock the organization row to serialize invariant checks. Invitation acceptance is transactional and exact verified email constrained at the route layer. No claim that these M03 workflows are already implemented.

Migrations use explicit BEGIN/COMMIT and are applied with `npm run db:migrate` to the configured dedicated development database. Never run migrate reset or destructive seeds on an unknown DB. Failed transactional migrations must be inspected (schema plus _prisma_migrations) before resolve/retry; never mark a migration applied without evidence. Before forward migrations, checkpoint and back up any meaningful development data. Disposable test schemas use random identifiers inside an explicit *_test database and are dropped only by the owning harness. Test database guard rejects the development DB, non-test DB names, missing NODE_ENV=test and production settings.

`demo:down` stops only this Compose project and retains volumes. It does not delete data. Backup/restore/upgrade demonstrations arrive at M09; hosted production is not authorized by local migration tooling.

M03 adds Organization.membershipRevision. Every membership mutation, invitation create/revoke/accept and resend writes this organization row inside a serializable transaction. Concurrent Admin changes cannot both act on an old count: serialization conflicts retry the complete authorization/invariant check. An organization must retain at least one Admin. Invitations store only token digests, bind the recipient's exact normalized verified email, expire after seven days and are consumed once. Resend creates a fresh invitation and revokes earlier pending invitations for that email in the same organization; it does not expose raw tokens via listing. Accept preserves an existing membership rather than duplicating or changing its role implicitly.

M04 adds tenant-anchored spaces/pages/drafts and version storage supporting the published-version foreign key. M05 supplies publication behavior. Composite foreign keys enforce same-organization spaces and same-organization/same-space parents. PageDraft is unique per page. Draft and structure revisions are independent; conditional draft updates reject stale content, while all tree create/move operations write the shared Space.treeRevision under serializable isolation to prevent concurrent cycles/depth violations. Tree depth is capped at ten, including moved descendants. Reader/Reviewer tree queries count and serialize published versions only; draft reads/saves require edit capability. Rich text is schema-validated and text-length bounded server-side; React renders only known semantic nodes and escaped text, with safe URL checks and no arbitrary HTML injection.

M05 adds snapshot parent/space/draft-revision metadata and a page-scoped idempotency key. The immutable-version trigger prevents update/delete; future migration/repair must explicitly account for this protection. Publication, latest pointer, safe audit and pending outbox insertion share one serializable transaction. The version full-text GIN index supports manual search; filtering joins only the current pointer and active page/space. Tenant-bound page-version outbox events are durable but not dispatched until M07. PostgreSQL search_path is set to the validated internal schema so raw SQL and ORM operations use the same disposable test schema. Migrations preserve pre-existing synthetic versions rather than resetting data.

M07 adds a Job table anchored to the same-tenant outbox event, lease token/expiry, three-attempt cap and durable backoff. IndexState is keyed by tenant, source type/ID/version and generation, with database-validated source relationships and status values. `npm run worker` is a separate low-concurrency process; SIGTERM stops new claims and drains active work, while abrupt termination is recovered after lease expiry. Keep workers stopped during schema changes. Back up before migrations; recover a failed deployment by inspecting Prisma migration status and the specific failed SQL, never resetting an unknown database. Old source jobs may finish but are excluded by fresh eligibility checks. No chunk/vector/embedding tables are installed in foundation.
